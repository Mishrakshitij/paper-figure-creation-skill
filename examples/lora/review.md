## Actual skill/tool issues

1. During the concurrent skill build, required references were temporarily missing. Work continued on source extraction and brief/spec preparation; evidence.md was read before rendering quantitative figures.
2. SKILL.md initially used an unsupported `--output-dir` renderer argument; this was reported to root and corrected there to `--output`. I did not patch the skill.
3. The initially documented evidence reference filename disagreed between SKILL.md and spec-format.md. This was reported; the final required file was available and read as evidence.md.
4. A direct original-PDF download returned HTTP 403. The web tool's parsed original PDF text worked. Its screenshot call exposed only a reference string in the current wrapper, so source-table pixels were not independently inspected here. The figures' own PNG/PDF pixels were inspected successfully.
5. A requested independent source-check subagent could not spawn due to the active thread limit. An available parent-team reviewer instead performed a pixels-first comprehension review after the initial exports. No full independent table transcription audit is claimed.
6. Custom Matplotlib geometry was chosen for the aligned parameter-count column and paired dot plots; the optional bundled renderer was not used to author the final pair. The bundled evidence validator was exercised on real reported data. This test therefore does not certify every renderer or draw.io path.

## Independent comprehension check

The parent-team visual reviewer inspected pixels before the brief and reported: the task, frozen W0 plus trainable low-rank BA, and -0.4pp WikiSQL/+2.2pp MNLI trade-off were immediately recoverable. The reviewer independently identified the same initial header collision, empty merge circle, and tight B-init/task-loss spacing. Those observations prompted the documented repairs. The reviewer then inspected v3's actual pixels and reported that the headings were separated, the plus was visible, and initialization/task-loss labels no longer crowded. The task, states, A-to-B route, and merged inference remained readable; the reviewer found no remaining blocker.

The final regeneration script calls the live evidence validator for both current specs, saves fresh reports, and refuses to render on validation errors. It supports an explicit `--skill-root` and ancestor-repository discovery; no scratch-specific source path is embedded in code. Matplotlib, NumPy, and Pillow are recorded in requirements.txt.

## Material limitations

- No actual venue/manuscript layout was available; the pair is a publication-scale draft, not a certified submission-ready asset.
- Source verification used parsed original PDF text, not table-page pixels; no independent source-data audit was possible within the available slots.
- Typical SD is not an entry-level CI; the tiny WikiSQL difference must not be interpreted as statistically established superiority or inferiority.
- The method deliberately represents one adapted projection and omits the remaining LM and its loss graph. The original experiments vary rank/projection configurations; the diagram does not assert one universal Table 4 configuration.
- Grayscale review and redundant marks were checked; a full color-vision simulation and physical print were not performed.
- No performance comparison against a baseline figure-making workflow was run; this is a forward behavioral test, not evidence of general skill superiority.
