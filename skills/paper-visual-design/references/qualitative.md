# Qualitative / technical comparisons

Preserve the existing [qualitative comparison workflow](../foundation/references/qualitative-comparisons.md). Read it for requests to show where or why a method works using recorded examples, outcomes, criterion-level measurements, or prediction diagnostics.

Align the same input across methods and disclose the case-selection rule. Keep observed outputs distinct from constructed examples or generated illustrations. Retain failures, missing measurements, and contrary cases; a curated visual example alone does not establish general performance.

Match crops, scales, coordinates, and diagnostic conditions. Distinguish shared architecture from shared weights and hold relevant input/state fixed for technical comparisons. An outcome, a prediction-error measurement, and a causal explanation are different claims. State hypotheses as hypotheses unless controls justify stronger conclusions.

Use exact graph panels for measured criteria and source-permitted observed images for qualitative evidence. Never generate an image that impersonates a model output. Keep one canonical source and review the figure inside the manuscript when integration is requested.
