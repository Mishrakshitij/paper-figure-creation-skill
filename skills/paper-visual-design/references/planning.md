# Plan the visual argument

Write the smallest useful plan before rendering. Inspect sources, not only the abstract. For a revision, identify concrete reader misunderstandings in the existing pixels; keep correct semantics and objects stable.

## Figure inventory

Map each central reader question to a figure or panel. Record omitted routes and why. A methods paper may need teaser + method + graphs; a benchmark paper may need teaser + setup + graphs, without architecture. A performance-plot request may need only graphs. A requested setup with no substantive source remains unresolved, not fabricated.

Use the user's venue template. Otherwise start a clearly labeled 7-inch/two-column draft, usually with 8–9 pt body labels; the actual template controls submission dimensions. Separate dimensions of an individual plot from the assembled figure. Scaling a 7-inch plot into a 3-inch slot also scales all its text.

## Three compositions for complex figures

Sketch topology, proportional areas, and first/second/third reading stops. Change the representation, not just colors or box positions. Useful alternatives include:

- A concrete before/after example beside aligned evidence panels.
- A main computation spine with a magnified novelty inset and a separately routed training return.
- Parallel candidate lanes sharing one input and one evaluator, with an explicit selection operation.

Record why the selected composition answers the question with fewer ambiguities. Reject a layout that requires a visually false connection. If feedback routes dominate, separate training and inference or use a local inset. Keep one focal operation larger or more detailed than supporting context.

## Representation and evidence contracts

Define what each object is, which identity persists, and what each operation changes. For token/matrix/grid diagrams, record exact dimensions and indices before styling. Example values may be constructed only when visibly labeled illustrative; do not present them as sampled model predictions. A generated illustration of an object is not an observed experiment.

For every plotted quantity retain source/version, exact cell/file/row, method, metric/direction/unit, dataset/split, protocol, budget, and uncertainty definition. Log unresolved contradictions. Do not average incompatible settings or connect categorical conditions as if they were a continuous learning curve.

## Build order

1. Source ledger and scientific contract.
2. Three sketches when complex, then selected geometry.
3. Exact graphs at intended final size.
4. Vector mechanism objects and any useful generated assets.
5. Assembly from one canonical source.
6. PDF/PNG pixel review, repair, then caption/manuscript integration if requested.

The plan is a working artifact, not a permission checkpoint. Proceed under the user's task authorization.
